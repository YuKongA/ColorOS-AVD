# ColorOS v0.1.0 / r1 发布验证

日期：2026-10-11，Asia/Shanghai。发布包来自独立重建的 ColorOS 17.0.0.114 / Android 17 镜像，包含与镜像匹配的冻结启动代码。

| 检查 | 结果 |
| --- | --- |
| 构建产物 | 官方 OTA 哈希、原生库输入/输出哈希、21 项应用目录移除通过；相机 APK 的原厂 Signing Block 已保留 |
| 干净模板 | 重新创建 16 GiB ext4，根目录只有空 `lost+found`；不读取现有运行实例的 userdata |
| 自动测试 | 完整测试 135 项通过，新增引导脚本的 3 项校验/终端交接测试另行通过 |
| 独立新装 | 安装器从最终 xz 内容解压、逐文件校验、注册新实例并首次启动通过；测试注册表和端口与开发实例隔离 |
| 来宾状态 | Root、SELinux Enforcing、ADB 认证、已启动系统，以及来宾 ext4 超级块中的 16 GiB 容量通过 |
| 相机注册与拍照 | 全新 userdata 能注册并启动原生相机，前后摄各保存一张 1920×1440 JPEG；首次使用保留欢迎页面和权限请求 |
| 重复安装保数据 | 对相同版本重新安装，自动保存离线备份；操作前后的 userdata 与加密密钥文件哈希完全一致 |
| 注销 | 默认卸载移除注册信息，全部 userdata/密钥字节保持一致 |
| 删除实例数据 | 输入 QA 实例名称确认后，仅对应 `.avd` 数据目录被删除，发布固件继续保留 |
| 分卷 | xz 压缩内容合计 5,714,403,224 bytes（约 5.32 GiB）；重新切为 256 MiB 小卷后，拼接数据的 SHA-256 与原始压缩内容一致 |

发布验收发现重写相机 APK ZIP 会丢失 Signing Block，导致全新系统扫描跳过 APK。已修复元数据保留，并重新生成系统镜像和发布内容。该处理供可信系统分区扫描读取证书身份，不是对修改后的 APK 内容重新签名；普通用户 APK 完整签名验证仍然适用。

本次照片验收使用隔离 QA 实例；测试时的授权、设置和照片不进入发布的空白模板。首次启动检查包含保持原厂引导入口的安装实例；相机操作验收使用了 `--skip-oobe`，不代表逐页开机引导或所有相机模式都已验收。

不提供实体多摄、人像和美颜；前摄缩放、4K/60fps、HDR、夜景算法和长期云服务兼容性未纳入本次发布验收。历史录像证据及能力范围见 [相机记录](coloros-camera-validation.md) 和 [兼容性说明](compatibility.md)。
